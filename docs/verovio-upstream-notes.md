# Verovio upstream notes

This ledger lists Verovio limitations we work around and the fixes we could offer upstream to [rism-digital/verovio](https://github.com/rism-digital/verovio). It was researched on 2026-09-30 against npm `verovio` **6.3.0** (`6.3.0-425dd7b`, released 2026-08-19). Source references use the `version-6.3.0` tag. Line numbers in `timeline.ts` move often, so that file is cited by function name.

GFC means a good first contribution: a small, self-contained change that is easy to review.

## Ledger

|---|---|---|---|---|---|
| 1 | **No written-pitch view of a concert-pitch score.** `transposeToSoundingPitch` works only from written to sounding pitch. The MusicXML importer also ignores `<concert-score/>` and `<for-part><part-transpose>`, so the imported MEI has no `trans.*` to go back from (probe confirmed). | None found. Closest is [#3593](https://github.com/rism-digital/verovio/issues/3593) "Use Transposition Function in Verovio for Score in Concert Pitch" (closed, and it asks for the opposite direction). | `src/lib/render.ts:259-260` engraves concert-basis scores as encoded. `src/components/Reader.tsx:83` forces the concert view. | (a) `iomusxml.cpp` `ReadMusicXmlPartAttributesAsStaffDef` (~l.1715): map `for-part/part-transpose` to `staffDef@trans.diat/@trans.semi` and record the concert basis. (b) Add a `transposeToWrittenPitch` option: `options.cpp`, `doc.cpp:1652`, and a `TransposeToWrittenPitchFunctor` in `transposefunctor.cpp` that mirrors `TransposeToSoundingPitchFunctor` (l.314+) with the interval inverted. | (a) yes, (b) medium |
| 1b | **Bug found while probing:** with `<octave-change>`, `trans.diat` is computed from `<chromatic>`. Tenor sax (−1/−2/oct −1) imports as `trans.diat="-9"` where it should be `-8`. The sounding-pitch output was still correct in our probe, but the exported MEI is wrong. | None found. The code dates from [#2725](https://github.com/rism-digital/verovio/issues/2725) "Support for `<octave-change>` at musicXML import" (closed). | None needed. We read MusicXML transposition ourselves in `src/lib/import.ts:14,121-125`. | `iomusxml.cpp:1727`: use `child("diatonic")` instead of `child("chromatic")` in `SetTransDiat`. It is a one-line fix plus a test file. | **yes** |
| 2 | **No endless layout beyond 100000 units, and no continuation mode.** `pageWidth` is capped at 100000 (`options.cpp:1120`). An out-of-range value is not clamped: it logs an error and silently resets to the default 2100 (probe confirmed). Every system start forces a clef and key redraw (`setscoredeffunctor.cpp:184`, `REDRAW_CLEF \| REDRAW_KEYSIG`), so each chunk of a long score starts with a clef and key. The meter is not repeated. | None found. | `src/lib/render.ts:17-19` (160-bar single system, then 120-bar chunks), `:256` (our own clamp), `:266`. | (a) Clamp out-of-range int options to min/max instead of resetting them, or raise the `pageWidth` max (`options.cpp`, `OptionInt::SetValue`). (b) Add an option or `sb` attribute to skip the clef and key redraw on a continuation system (`ScoreDefSetCurrentFunctor::VisitMeasure`). | (a) **yes**, (b) medium |
| 3 | **Text is laid out with fixed Times metrics.** Lyrics and text collide when drawn in a wider face. `fontTextLiberation` exists but is metric-compatible with Times, so it does not help. | [#4130](https://github.com/rism-digital/verovio/issues/4130) "Text layout issues with different fonts" (closed; maintainer says multiple text fonts are not planned). [#722](https://github.com/rism-digital/verovio/issues/722) "Change text font" (closed). [#4156](https://github.com/rism-digital/verovio/issues/4156) "Text Font Options" (closed). A smaller alternative is a "text metrics JSON" option: advance widths per glyph, loaded into `Resources` next to the `data/text` Times tables. | no (support #4404) |
| 4 | **The embedded SMuFL text `@font-face` makes every page much larger.** A one-page probe was 116.8 KB with `embedded` and 36.4 KB with `none`, about 80 KB per SVG page. The `linked` option points at a verovio.org URL, which does not suit offline or self-hosted apps. | None found. Related: [#4361](https://github.com/rism-digital/verovio/issues/4361) "Support for single-font WASM builds" (open). | `src/lib/render.ts:261` (`smuflTextFont:'none'`, `fontFallback`). `src/styles.css:1-3` self-hosts Bravura and Petaluma woff2. | `svgdevicecontext.cpp` `IncludeTextFont` (l.~129-150): add a `smuflTextFontUrl` option (a base URL for `linked`). Optionally emit a subset holding only the glyphs used. | **yes** (URL option) |
| 5 | **MusicXML import gives staves in multi-staff parts random IDs.** The part `staffGrp` gets the part ID (`iomusxml.cpp:1140`), and a single-staff `staffDef` reuses it (`:1578`). A multi-staff part's `staffDef`s get generated IDs, so nothing like `P1-s1` can be addressed across imports (probe confirmed). | None found. | `src/lib/render.ts:76-110` (`staffNumbers` maps parts through the `staffGrp` ID and child position, with a positional fallback). | `iomusxml.cpp` ~l.1575: when `nbStaves > 1`, `staffDef->SetID(partId + "-s" + n)`, or put it behind an option to keep existing IDs stable. | **yes** |
| 6 | **Timing gaps in the timemap and MIDI.** (a) One tempo per measure: `InitMaxMeasureDurationFunctor` (`midifunctor.cpp:262-302`) stores the last tempo seen in each measure. A mid-measure change therefore retimes the whole measure, and an earlier tempo in the same measure is lost. Our probe had ♩=60 on beat 1 and ♩=120 on beat 3; the whole measure played at 120. (b) A bare `<sound tempo>` directly under `<measure>` is ignored in 6.3.0. (c) MusicXML repeats, voltas and D.C./D.S. are not expanded automatically; expansion needs an MEI `<expansion>` plus the `expand` option. | (b) [#4442](https://github.com/rism-digital/verovio/issues/4442) "MusicXML import: bare `<sound tempo>` as a direct child of `<measure>` is ignored" (closed), fixed by [PR #4443](https://github.com/rism-digital/verovio/pull/4443) (merged 2026-09-04, **after 6.3.0**). (c) [#235](https://github.com/rism-digital/verovio/issues/235) "Support for MIDI export of repetitions" and [#3733](https://github.com/rism-digital/verovio/issues/3733) "Implement optional repeats expansion on MIDI output" (both closed and pointed to `<expand>`). Related: [#4153](https://github.com/rism-digital/verovio/issues/4153) "midi measures overlap on tempo changes" (closed). (a) None found. | `src/lib/playback/timeline.ts`: `sourceMarkers`, `traverse` (repeats and jumps), `tempoPoints`/`tempoAt` (tempo per beat), and the `verovioTimemap` cross-check inside `buildPerformanceTimeline`. | (a) Keep a list of tempo changes per measure (with `tstamp`) and integrate real time piecewise in `GenerateMIDIFunctor` and `GenerateTimemapFunctor`. (c) Have `iomusxml.cpp` synthesize an `<expansion>` from repeat barlines, endings and sound jumps. | (a) medium, (c) hard |
| 7 | **Toolkit reuse: no leakage found, but `resetXmlIdSeed(0)` is a no-op.** Seed `0` means "random" (`toolkit.cpp:1576`, where `m_xmlIdSeed` defaults to 0 = random). Our IDs are deterministic only because we pass `xmlIdChecksum:true`. A probe showed that reused and fresh toolkits give byte-identical MEI and SVG after `resetOptions()`, including after a previous transposed Petaluma render. | [#3231](https://github.com/rism-digital/verovio/issues/3231) "ResetXmlIdSeed" (closed, confusion about the API). | `src/lib/verovio.worker.ts:26-31`. Locally, the `resetXmlIdSeed(0)` call can be dropped, or a non-zero seed used. | Documentation only: state in the `resetXmlIdSeed` docs and the option help that 0 means a random seed. | **yes** (docs) |
| 8 | **Staff labels have no option to turn them off.** `header`/`footer: 'none'` are enough for page furniture. Labels need MEI surgery. | None found. | `src/lib/render.ts:154-157` removes `label`/`labelAbbr`/`@label`/`@label.abbr`. Removing `pgHead`/`pgFoot` there is redundant with `header/footer:'none'`. | Add a `staffLabels` option (`auto` / `abbr` / `none`) checked where `ScoreDefSetCurrentFunctor` calls `SetDrawLabels(m_drawLabels)` (`setscoredeffunctor.cpp` ~l.187). | **yes** |
| 9 | **Hiding staves needs a lot of MEI pruning.** Removing `<staff>`/`<staffDef>` is not enough: `@staff` lists on control events, and `startid`/`endid`/`plist` references into removed content, all have to be pruned or rendering breaks. Chord-symbol (`<harm>`) transposition works correctly (probe confirmed), so it needs no workaround. | Background in [#493](https://github.com/rism-digital/verovio/issues/493) "Hide an entire parts/stem/staff in the svg, including hairpin" (closed). ## Notes

- **Lyric density (`render.ts:31-52`).** We widen bars from our own count of syllables per staff and measure. It has not yet been separated from item 3, since collisions could come from the Times metrics or from our forced `<pb>` density. Build a minimal repro before filing anything.
- **Suggested order for upstream PRs:** 1b (a one-liner with a test) → 5 → 10 → 4 → 8 → 2a → 7 (docs). Items 1, 2b and 6a need an issue discussion with the maintainers first. Item 3 means contributing tests and feedback on PR #4404, not a competing PR.
- **Related upstream work to watch:** [PR #4375](https://github.com/rism-digital/verovio/pull/4375) "Add pitch position query API for rendered layouts" (open) could replace some of our SVG geometry reads. [PR #4409](https://github.com/rism-digital/verovio/pull/4409) "Fix: fontTextLiberation option silently ignored in toolkit" was merged before 6.3.0.
- When we upgrade past 6.3.0, re-check 6b (PR #4443) and remove any source-side tempo patching it makes unnecessary.
